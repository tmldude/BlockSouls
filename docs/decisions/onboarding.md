# Onboarding (v0.11 playtest fixes, 2026-10-12)

Answers playtest item 1 ("I don't know how to make anything / the guns", "couldn't repair a car") with three layers:
a recipe viewer in the pack, every recipe in the vanilla recipe book, and a tutorial advancement tab. Plus wreck hints.
Same rules as `DECISIONS.md` (the root file wins on conflict).

## Recipe viewer
- **EMI, else REI, else none**, decided when the pack is built: `modpack/add-mods.sh` tries `packwiz modrinth add emi`,
  then `rei`, and warns (doesn't fail) if neither has a 26.3 Fabric build. This sandbox can't reach Modrinth, so the
  CI `modpack` job's log (`recipe viewer: emi|rei`) is where the pick shows. Sides come from Modrinth metadata (both
  are client mods that are optional on a server); the Docker server doesn't use the pack, so it never loads them.
- REI pulls in its own dependencies (Architectury, Cloth Config) through packwiz; EMI has none.

## Recipe book
- **One vanilla recipe-unlock advancement per recipe**, generated by `tools/content/gen_recipe_advancements.py`, same
  shape as vanilla's data generator: `recipe_unlocked` + one `inventory_changed` criterion per key ingredient, any one
  is enough, reward = the recipe. Path `data/<ns>/advancement/recipes/<category>/<recipe>.json` where category is the
  recipe's book category (`misc` for smelting/smithing without one).
- **No `parent`.** Vanilla's recipe advancements hang off `minecraft:recipes/root`; ours don't need a tree (they have
  no display) and a missing parent would drop them, so they're standalone.
- **Key ingredients = the recipe's BlockSouls ingredients**; a recipe made only of vanilla items (primary ammo) keys on
  all of them. So holding Scrap unlocks the gun receiver/stock, scrap-plate armor, wheel, engine and fuel can;
  holding a Gunmetal Ingot unlocks the barrel, ammo and armor; holding gun parts unlocks the guns.
- **Extra key: Scrap also unlocks the gunmetal smelting/blasting recipes** (raw gunmetal and both ores). Scrap is the
  first BlockSouls item a player finds, and the furnace book then shows where gunmetal comes from. Extra keys live in
  the generator's `EXTRA_KEYS`.
- **Load conditions copied from the recipe** (plus any module an extra key needs). In 26.3 advancements are a
  reloadable registry: an unknown item id, or a `recipe_unlocked` naming a recipe that didn't load, fails the
  registry, so recipe and advancement must load or skip together.
- **Check (R3):** `check_recipe_web.py` (CI's "Check the crafting web" step) now also fails when a recipe has no
  unlock advancement, an unlock advancement names a recipe that's gone, or a generated file is stale. Fix: rerun the
  generator. `docs/CONTENT.md` documents it.

## Tutorial tab ("BlockSouls")
- **Root** `blocksouls:tutorial/root` lives in `common` (nested in every module, so the tab always exists); granted on
  the first tick (`minecraft:tick`), no toast. Background: vanilla deepslate tiles. Icon: crafting table.
- **Three chains**, each step's description says how to do the next thing, in mechanics:
  - guns: Scavenger (hold Scrap, `world`) → Gunmetal (hold a Gunmetal Ingot, `world`) → Parts Bin (any gun part,
    `guns`) → Locked and Loaded (any crafted gun type; the starter pistol doesn't count; goal);
  - kart (`vehicles`): Fixer-Upper (right-click a Kart Wreck) → Spare Parts (fit a Wheel *and* an Engine) → Patched
    Up (fit scrap) → Grease Monkey (ride a Kart; goal). All vanilla `player_interacted_with_entity` /
    `started_riding` criteria; the wreck's part interaction counts as an item interaction, so the item filter works.
  - run: First Light (survive a night, `game`) → Blessed (first boon, `game`) → Fog Gate (any of the four field
    bosses, `bosses`, goal) → Crownbreaker (the Hollow Sovereign, `bosses`, challenge).
- **Each advancement sits in the module that owns its trigger item/entity**; a cross-module parent or item gets
  `fabric:all_mods_loaded` (gun steps need `world`, boss steps need `game`).
- **Titles and descriptions are translation keys in `common`'s `en_us.json`** (`advancements.blocksouls.tutorial.*`),
  one file instead of five so parallel sessions' lang edits don't conflict.
- Descriptions quote real recipes (counts from the recipe JSON) and the default wreck parts; if a recipe changes,
  update the line in `common`'s lang file.

## Contract additions (`common`)
- **Criterion `blocksouls_common:milestone`** (`common.advancement.MilestoneTrigger`, registered by `Milestones`):
  conditions `milestone` (`night_survived` | `boon` | `boss_killed`), optional `id` (boss or boon id) and `value`
  (night number bounds). Fed from the existing events, so no module grants advancements itself and no new event was
  needed: `RunEvents.DAWN` → `night_survived` for every non-spectator online player; `PlayerRunEvents.BOON_GRANTED`
  → `boon`; `BossEvents.KILLED` → `boss_killed` for every credited player. `Milestones.init()` is one new line in
  `BlockSoulsCommon.onInitialize`.

## Wreck hints (`vehicles`)
- **While a player holds a wheel, engine or repair scrap** (either hand), every Kart Wreck within `hints.radius`
  (12 blocks) puffs `hints.particles` (4) green sparkles, sent **only to that player**, every `hints.intervalTicks`
  (10); the nearest wreck's missing parts go on the action bar: "Needs: 2 Wheels, Engine, 8 Scrap" (parts already
  complete are left out; 1 shows the bare name). Off with `hints.enabled = false`. Downed and spectating players get
  none.
- The hint shows whatever part is held, not just ones the wreck still needs: the point is "this is where parts go".
- `RepairProgress.remaining(cfg)` is the pure "what's missing" (unit-tested).
- **Tooltips** (client, gray, mechanics only): Wheel / Engine "Right-click a Kart Wreck to fit it (a wreck takes N)",
  Fuel Can "Right-click a Kart to refuel N% of a tank", N from config.

## Tests
- `integration` `OnboardingGameTests`: holding Scrap unlocks recipes in four modules (and not the guns); every
  BlockSouls recipe has an unlock advancement at runtime; the guns chain's first step grants on scrap, dawn grants
  First Light, a field boss grants Fog Gate but not Crownbreaker, the final boss does.
- `vehicles` `wreckHintNamesWhatItStillNeeds`: no hint with a non-part in hand; with a part, the nearest wreck is
  hinted and its message names wheels, engine and scrap but not fitted parts.
