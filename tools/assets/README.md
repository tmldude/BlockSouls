# Placeholder assets

`gen.py` makes deterministic, in-theme pixel art so no session waits on real art:

```sh
python3 tools/assets/gen.py <kind> <palette> <out.png> [--seed NAME]
# e.g.
python3 tools/assets/gen.py ore rad world/src/main/resources/assets/blocksouls_world/textures/block/uranium_ore.png
python3 tools/assets/gen.py skin blight mobs/src/client/resources/assets/blocksouls_mobs/textures/entity/screamer.png
```

- **kinds:** `block`, `ore`, `ingot`, `item`, `gun`, `helmet`, `chestplate`, `leggings`, `boots` (16×16),
  `skin` (64×64 humanoid layout, vanilla zombie UVs).
- **palettes** (pick by theme): `scrap`, `rust` (scavenged), `blight` (Nether infection), `rad` (radiation),
  `ember` (Furnace Knight), `pale` (Pale Rider), `storm` (Stormplate Knight), `ash`, `bone`, `steel`, `wood`,
  `rot` (rotting flesh), `flesh` (raw, mutated).

Same arguments → same image; the seed defaults to the file name. Commit the generated PNGs. The art sessions
replace them later at the same paths, so keep paths stable.

## Mob art (`mobs` module)

The mobs' art is generated by four scripts that share one geometry spec, so the model, its texture, its
screenshots and its sounds can't drift apart:

```sh
python3 tools/assets/mob_models.py        # spec -> mobs/src/client/.../model/MobGeometry.java (+ UV packing)
python3 tools/assets/mobs.py              # skins, _glow layers and spawn eggs, painted on that UV layout
python3 tools/assets/mob_preview.py       # renders every mob -> tools/assets/previews/<mob>.png (+ --hitbox)
python3 tools/assets/mob_sounds.py        # synthesizes every mob sound -> .ogg + sounds.json (numpy + ffmpeg/libvorbis)
python3 tools/assets/check_mob_assets.py  # fails if MobGeometry.java is stale or a texture/sound is missing
```

- **`mob_models.py`** lists each mob's parts (pivot, rest rotation, cubes) in Minecraft model space. UV offsets are
  packed automatically, so add or resize cubes freely, then re-run `mob_models.py` and `mobs.py`. Never edit
  `MobGeometry.java` by hand. Animations stay hand-written in each `*Model.setupAnim`.
- **`mobs.py`** paints with per-mob color ramps and named cube faces (`c.face("skull", "front")`; on a front face
  x = 0 is the mob's right side). Glow layers are transparent except what should shine.
- **`mob_preview.py`** is a small software rasterizer that builds cubes, UVs and poses exactly like
  `ModelPart`; its walk/telegraph poses approximate the Java animations. Sheets show front, side, back, walk, the
  attack telegraph, and the telegraph shrunk to how it reads ~20 blocks away.
- **`mob_sounds.py`** builds voices from a glottal pulse train shaped by moving vowel formants, plus filtered noise,
  clicks, bubbles and impacts. Seeded, so re-running gives byte-identical files.
